## Debate summary

- **Current control:** `Sources/LightningDesk/Components/MiniCandleChart.swift` is a shared native SwiftUI `Canvas` chart. It already draws candles, axes, current-price/strike lines, Candidate001 annotations, OHLC scrubbing, and optional zoom/pan. `MacTradingWorkspace` is macOS-only, but `MiniCandleChart` also serves iPhone views. A global replacement would change iOS behavior.
- **First spike candidate:** [SwiftUI-Data-Visualization](https://github.com/muhittincamdali/SwiftUI-Data-Visualization). Release v2.0.2 exists; its annotated tag resolves to source commit `4d1f75caa39a75c844d4f4bad1a3f3f9638aa836`. The tag is unsigned, so the spike pins that commit SHA directly. Its Package.swift at that commit requires Swift tools 6.2 and declares macOS 14/iOS 17; it has no external package dependencies and carries an MIT license (license file SHA `69a6fb9f722ed0e9b3ebf3c5e8e85ed5a49b4dcb`). The API uses Date + OHLC and exposes candle accessibility values. The upstream README reports 188 tests. Local toolchain is Swift 6.4.2 / Xcode 27.2.
- **Deferred comparison candidate:** [ChartLens](https://github.com/ShiinaLabs/chart-lens). Its manifest documents macOS 14/iOS 17 and Swift 6.0; its license is Apache-2.0; its chart uses numeric x-values and offers generic overlays, hit-testing and zoom. GitHub shows thinner activity/release evidence. The README recommends 1.0.0, but its tag-to-commit mapping is unverified, so do not resolve or use it unless a specific first-candidate gap makes the comparison necessary and an immutable revision is confirmed.
- **Counterargument:** a chart library will not fix BlazerOS-owned candle validity, quote freshness, source-bar identity, ORB state markers, plan-only/manual-execution wording, or accessibility contracts. The current canvas already has useful interaction and would be replaced at real integration cost.
- **View-model contract:** each bar needs stable source/provider, environment, instrument, granularity and UTC start identity; bid/ask/mid provenance; finite, positive, internally consistent OHLC; strict chronology; explicit completion state; and preserved gaps. Quotes carry broker as-of time, receive time, source/environment and bid/ask. Markers bind to bar/time/price plus strategy/version evidence. Stale or missing quotes cannot be drawn as current. Accessibility must expose selected time, timezone, source and OHLC. Plan markers stay labeled as informational and manual-only.
- **Other project decisions:** use [OANDA v20 OpenAPI](https://github.com/oanda/v20-openapi) as a static schema reference only and cross-check behavior against [current candle/instrument docs](https://developer.oanda.com/rest-live-v20/instrument-df/); the spec [changelog](https://github.com/oanda/v20-openapi/blob/master/ChangeLog) is old. Do not use [LEAN OANDA backtests](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/brokerages/supported-models/oanda) as cost-adjusted validation without custom fee and fill models; QuantConnect documents immediate fills, null slippage, and zero fees for its OANDA model. Keep native banners; the [SwiftUIToast](https://github.com/ivan-magda/swiftui-toast) queue has no demonstrated gap to solve. These are audit recommendations, not dependency or integration approvals.
- **Toast:** keep the native Mac banners. Reconsider [SwiftUIToast](https://github.com/ivan-magda/swiftui-toast) only if a demonstrated queueing or accessibility requirement is unmet.
- **OANDA types:** the [official v20 OpenAPI spec](https://github.com/oanda/v20-openapi) is a source to compare with the existing hand-written request/response types. No generated client is authorized by this evaluation.
- **Research engine:** [LEAN OANDA brokerage plugin](https://github.com/QuantConnect/Lean.Brokerages.OANDA) is only a separate research-lab candidate. Its default OANDA backtest assumptions do not establish slippage-adjusted evidence. No trading engine, provider, credential, or order integration is in scope.

## Plan and design

1. Preserve `MiniCandleChart` as the comparison control and all existing app code.
2. First test the simpler Date + OHLC API in a disposable, macOS-only spike. Keep the spike outside `LightningDesk` and the iOS app target; use synthetic, deterministic bars and no OANDA access.
3. `MiniCandleChart` is internal to the shared `LightningDesk` target, so a standalone spike cannot call it without changing production visibility. Use a clearly labeled Canvas control port for limited visual/interaction comparison. Mark production-render parity unverified; if this approximation prevents a fair comparison, stop without recommending adoption. BlazerOS remains owner of freshness, marker identity, plan semantics and data validity; a package may only render the supplied view-model.
4. Consider ChartLens only if the first candidate fails a specific required interaction or overlay gate that ChartLens appears to satisfy.
5. Decide **advance to an isolated production integration proof / hold / reject both** from captured evidence. The spike cannot adopt a production dependency because it uses a Canvas control port rather than the actual internal `MiniCandleChart`. Any later production dependency decision requires a separate reviewed integration checklist and actual Mac-vs-iPhone build verification.

## Acceptance gates for the chart spike

- Exact package revision and license verified from the upstream repository; toolchain and macOS deployment compatibility established before resolution.
- Mac-only isolated build; no change to the shared iPhone chart path, `Package.swift` of the product, OANDA services, credentials, or orders.
- Same deterministic 125- and 500-bar synthetic EUR/USD and GBP/JPY data shown in both renderers. Confirm chronology, OHLC values, decimal precision, gaps, and time-zone labels. Both panes must map X to elapsed UTC time and show missing intervals as gaps; the Canvas port cannot space all bars uniformly.
- Compare the labeled Canvas control port with the candidate: candle selection/scrub with correct time and OHLC; zoom/pan; fresh, stale and missing quote presentation; and plan/ORB marker overlays. Quote identity/as-of stays anchored to the latest source quote regardless of viewport; stale quotes must be clearly labeled in both panes or suppressed as a current-price line. Pan/zoom must clear or reconcile selection so the readout and crosshair identify the same visible source bar. Marker IDs must round-trip to the intended source bar and price after pan/zoom; chart Y domains must include visible quote/plan levels. Production renderer parity remains UNVERIFIED unless directly established without product changes.
- Accessibility exposes candle data and provides working keyboard/VoiceOver alternatives for selection and zoom; a generic chart label alone does not pass.
- Visual check at 1440×820, 1280×800, and 1040×708; confirm no clipping or unreadable axes. No product iPhone files may change in this spike; actual iPhone product-build/renderer acceptance is deferred to any later production-proof checklist.
- Record build warnings and a bounded warm redraw/scrub performance comparison at 500 bars with at least 30 warm samples per renderer and interaction. Report p50/p95/max, sample count, machine and toolchain. The ≤33 ms p95, ≤250 ms max, and ≤10% regression thresholds are advisory for the Canvas port; they are not proof of production performance. Mark unavailable or unreliable measurements unverified.
- No chart content can authorize an order or imply a fill. Package source is fetched only for the build; the spike has no runtime network, OANDA, or Keychain access.
