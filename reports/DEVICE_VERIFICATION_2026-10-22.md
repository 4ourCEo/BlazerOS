# Device verification — 2026-10-22

Scope: confirm the current `main` (Swift 6 app target, logic-test suite, CI builds) still
builds, signs, installs and runs on the test iPhone, and record what remains manual.

Device: **Gilbert's iPhone** — iPhone 16, iOS 27.0 (24A435), paired over the wired tunnel.

## Build and signing

- `xcodebuild -project iPhone/BlazerOS.xcodeproj -scheme BlazerOS -destination 'platform=iOS,id=…' -configuration Debug -allowProvisioningUpdates build` — **succeeded**.
- Entitlements on the app, `BlazerWidgets.appex` and `BlazerLiveActivity.appex`:
  `com.apple.developer.team-identifier = 8GZ3352QQB`,
  `com.apple.security.application-groups = [group.com.blazer.os]`; Debug carries `get-task-allow`.
- Embedded content: `BlazerIntents.framework`, `BlazerActivity.framework`, the widget and Live
  Activity extensions, and **one** `BlazerCore_<hash>_PackageProduct.framework`.
- `devicectl device install app` — **installed**.

## Known issue found during this run

Launching the build logs one dyld warning per BlazerCore class: the app binary carries a static
copy of BlazerCore while the embedded `BlazerCore_<hash>_PackageProduct.framework` is also
loaded. Release device builds duplicate the classes too. Tracked in
[issue #6](https://github.com/4ourCEo/BlazerOS/issues/6) with the link graph and the attempts
made so far.

## Still manual

The physical-device gate in
[RELIABILITY_RELEASE.md](RELIABILITY_RELEASE.md#remaining-gate-physical-device) is unchanged:
venue confirmation in Pocket Option, Airplane Mode refusal, permission denial, widget
`HISTORICAL` / Live Activity `EXPIRED` expiry, repeated Siri invocations, and the 3 m / 5 m
handoff rows all require a person holding the phone. None of them can be driven by
`devicectl`; they are not regressions, just unverified here.
